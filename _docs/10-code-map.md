## Reference material — read-only

**These live on the Desktop, NOT inside the project.** Paths are relative to
`<desktop>/`, not to the server root:

```
some_source_code/latest_dev_scape/       best Phoenix scrape
  gamemodes/fallout/                     their schema: 94 plugins, 2057 files
  gamemodes/nutscript/                   their FORKED framework
    gamemode/core/libs/sh_anims.lua      source of our animation data
    gamemode/core/meta/sh_rarity.lua     the rarity system, worth porting
  addons/longsword_fallout/              177 weapon definitions
  addons/meleearts2*/                    melee source
some_source_code/old1_client_scrape/<scraped-server>_27064/   the LIVE server
  gamemodes/fallout/schema/fallout_ui/   the Fallout UI - see 16-ui.md
  gamemodes/fallout/schema/tgui/         a second, smaller widget set
phoenixsourceaddons/                     every Phoenix workshop addon, unpacked
```

**`find` does not work reliably in these trees.** The content junctions make it
bail silently - it returns nothing for files that demonstrably exist. Use
Python's `os.walk` for any exhaustive search.

Comparing dev vs live is how the fire-rate question got settled — 13 weapons
were rebalanced between them.

## Tools — `_docs/tools/`

| Script | Use |
|---|---|
| `luacheck.py <dir>` | block-balance check on every `.lua`. Handles GMod's `//` comments. **Run after every edit** — it's the only syntax check available without booting |
| `resolve_asset.py <paths>` | does an asset exist, and which addon provides it. `--swep <dir>` checks every SWEP's models; `--search <name>` finds candidates |
| `vmtcheck.py <dir> [--fix]` | finds and repairs malformed `.vmt` files. Run after installing or updating any content addon — these errors never reach Lua |
| `luaglobals.py <dir>` | Finds reads of names never bound in the file — the **nil-global** class `luacheck.py` cannot see, because the file still parses. Re-learn after adding globals: `--learn <dirs>` |
| `content_map.py` | regenerates `09-content-map.md` |

`luacheck.py` is a **tokenizer** — it catches unbalanced
`end`s, which is the common failure when editing large files, but not every
syntax error.
